# Новости в канале через обычного Telegram-бота

Используется бот магазина, например @ReversVPNbot. Не нужны my.telegram.org, api_id,
api_hash, номер, код входа и Telethon. Установщик переносит сохранённый токен магазина
в отдельный закрытый файл. Генерация: Ollama + Qwen3 0.6B (веса около 523 МБ).
Платные API не нужны. Публикация по умолчанию каждый час.

## Настройка

1. Добавь бота магазина в свой канал администратором с правом **Публикация сообщений**.
2. На VPS выполни:

```bash
cd ~/ReVPN
git pull --ff-only
sudo bash install.sh --update
sudo bash install-channel.sh
sudo revpn-channel configure
```

Укажи @username канала либо его числовой ID (-100...). Остальные настройки можно
оставить через Enter. Скрипт проверяет права и сохраняет числовой ID канала.
Ссылка-приглашение приватного канала не заменяет ID.

3. Посмотри результат без публикации и включи службу:

```bash
sudo revpn-channel preview
sudo systemctl enable --now revpn-channel
```

Первый пост готовится сразу после запуска, последующие — через час после публикации.
Если свежего материала нет или RSS недоступен, выпуск пропускается.
Источники: Хабр, 3DNews, iXBT и OpenNET. При обновлении эти четыре RSS добавляются к сохранённым, без дублей. Недоступная лента не блокирует остальные.
Другие HTTPS RSS/Atom-ленты можно указать при configure.

## Управление

```bash
sudo systemctl stop revpn-channel
sudo revpn-channel configure
sudo revpn-channel check
sudo revpn-channel preview
sudo systemctl start revpn-channel
journalctl -u revpn-channel -n 40 --no-pager
```

`check` проверяет права без публикации. `preview` генерирует новый пробный текст только
в терминале. `once` готовит и публикует один выпуск (службу сначала остановить).
Настройки: `/var/lib/revpn-channel/channel.json`. Токен: `/var/lib/revpn-channel/bot-token`.
Редактор не имеет доступа к платежным токенам или паролю панели. Его модуль не вызывает
getUpdates и не меняет webhook, поэтому не конкурирует с магазином за сообщения.

Обычный `install.sh --update` обновляет ранее установленный модуль канала и токен из магазина.
Идентификатор канала, модель, история и очередь сохраняются. Однократно интервал становится 1 час, обновляется редакционный стиль, включаются фото и убирается подпись источника. Старые api_id/api_hash убираются из конфигурации.
Оставшаяся старая Telegram-сессия не используется; её можно отозвать в Telegram → Устройства.
При новой установке служба сама не включается. При обновлении активная служба перезапускается.

## Формат и ограничения

Живой русский пересказ: жирный заголовок, 3–5 коротких абзацев, 2–3 эмодзи. Ориентир 1000–2200 символов, максимум 3200; если фактов мало, пост короче. Берётся до 7000 символов материала из RSS; полный текст сайта отдельно не скачивается. Ссылка источника в публикации выключена (`show_source: false`), URL остаётся в RSS для учёта повторов.

Фото выбирается из image-enclosure/media или HTML материала RSS. Новости без подходящего HTTPS JPG/PNG пропускаются при `photos: true`. Внешний сервер изображения должен быть доступен Telegram. Текст до 1024 UTF-16 единиц публикуется подписью фото; длиннее — фото с заголовком и текст следующим сообщением. Между этими отправками сохраняется ID фото, чтобы повтор после явной ошибки не дублировал картинку. При неопределённой ошибке требуется ручная проверка.

Для возврата ссылки установи `show_source: true`; для текстовых новостей — `photos: false`. Уже подготовленные записи очереди сохраняют прежний вид.  Материалы старше 48 часов и ранее использованные ссылки пропускаются.
Маленькая модель может ошибаться; сначала проверь качество preview. Модель не получает токены,
права запуска команд или доступ к перепискам. Ollama вызывается через localhost.

Bot API не поддерживает идемпотентную отправку. Если соединение оборвалось и неизвестно,
дошёл ли пост, он получает статус `uncertain` и не отправляется повторно автоматически.
Публикации в этом канале ждут ручной проверки. Это предотвращает автоматические дубли.

```bash
sudo systemctl stop revpn-channel
sudo revpn-channel status
# Если пост с ID 7 уже есть в канале:
sudo revpn-channel resolve --post 7 --result sent
# Если его нет и этот выпуск нужно пропустить:
sudo revpn-channel resolve --post 7 --result skipped
sudo systemctl start revpn-channel
```

При Telegram 429 учитывается retry_after; обычные ошибки прав или неверного запроса
оставляют пост в очереди. При переходе с Telethon старая незавершённая очередь помечается
неопределённой и требует такой же проверки. У свежей установки очереди нет.

## Платежи магазина

Новые счета только реальные (`is_test=false`). Обновление отключает старый тестовый режим.
Старая демо-ссылка не превращается в реальный счёт: создай новый заказ.

### Расписание версии 3

Обновление сохраняет канал, токен, модель и историю постов. По Москве:
- Будни: 10:00, 15:00, 20:00.
- Суббота, воскресенье, июнь–август и основные праздничные даты РФ: 09:00, 12:00, 15:00, 18:00, 21:00.
- Дополнительные выходные/переносы задаются в `extra_holidays` списком дат `YYYY-MM-DD` в `/var/lib/revpn-channel/channel.json`. Автоматической загрузки ежегодного производственного календаря нет.

Выпуск возможен в течение часа после назначенного времени. Пропущенные выпуски после длительного выключения не публикуются пачкой. При отсутствии пригодного материала или ошибке модели выпуск может быть пропущен.

Срочный отбор версии 4 не имеет закрытого списка тем. Все свежие материалы из `breaking_feeds` и обычных `feeds` оцениваются Ollama по общественной значимости, последствиям и необходимости немедленной публикации. Смерти известных людей, позитивные события и новые темы обрабатываются тем же способом. Требуется высокая оценка значимости и срочности, затем смысловое сопоставление с сообщением другого сайта. Совпадение двух сайтов не означает независимой проверки фактов. Ошибочный JSON или сбой модели не разрешают публикацию.

Проверка запускается примерно раз в 5 минут плюс время загрузки и работы модели. На слабом VPS задержка может быть заметной. За проход оцениваются до 12 ранее не проверенных материалов за последние 2 часа; результаты сохраняются, изменённый текст оценивается заново. При большом потоке или слабой модели возможны пропуски. Это не мониторинг всего интернета: охват определяется доступными RSS. Для срочных сообщений фото необязательно. `breaking_enabled: false` отключает внеплановые публикации. Журнал показывает ошибки RSS и результаты отбора.

Подпись «ReVPN. Новостной канал» содержит ссылку на публичный канал, полученную из Telegram. «Читать далее» и одинаковые абзацы удаляются. В декабре генератор получает указание использовать уместный новогодний тон, а ностальгию по 2021 году — только при связи с материалом. Для трагедий и срочных сообщений праздничный тон не используется.

Обновить без повторного ввода настроек:
```bash
cd ~/ReVPN
git pull --ff-only && sudo bash install-channel.sh --update
sudo systemctl enable --now revpn-channel
sudo systemctl restart revpn-channel
```

Предпросмотр без публикации: `sudo revpn-channel preview`.
