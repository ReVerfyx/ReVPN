# ИИ-редактор Telegram-канала

Отдельный юзербот (Telethon), входит в обычный Telegram-аккаунт администратора канала.
Генерация локальная: Ollama + Qwen3 0.6B. Платный API не нужен. Около 523 МБ загрузки весов,
дополнительно нужна RAM для работы модели; на CPU подготовка поста может занять несколько минут.
Служба магазина и редактор работают независимо. У редактора отдельный системный пользователь,
ему не передаются токены магазина, платежи или сообщения покупателей.

## Установка на том же VPS

```bash
cd ~/ReVPN
git pull --ff-only
sudo bash install.sh --update
sudo bash install-channel.sh
sudo revpn-channel configure
sudo revpn-channel login
sudo revpn-channel preview
sudo systemctl enable --now revpn-channel
```

`install-channel.sh` устанавливает Telethon в отдельное окружение, Ollama (официальным установщиком,
если отсутствует) и скачивает модель. Конфиг/сессия при повторном запуске сохраняются, публикации
после повторной установки нужно снова включить командой systemctl выше.
Обычный `install.sh --update` обновляет также код уже установленного редактора и перезапускает
его только если он был активен. Учётные данные повторно не запрашиваются.

## Что получить

1. https://my.telegram.org → API development tools → создать приложение: получить `api_id` и `api_hash`.
2. Аккаунту, которым входишь, дать право публикации в своём канале.
3. В `configure` указать `@username` канала (или числовой ID известного аккаунту канала), RSS-источники, стиль и интервал. По умолчанию — один пост каждые 2 часа.
4. В `login` ввести номер, код Telegram, пароль 2FA при наличии. Вводить только на VPS.
   Скрипт проверит права и закрепит числовой ID канала, чтобы смена username не перенаправила посты.

Команда `preview` только печатает новый текст в терминале. Для публикации именно нового
поста вручную: остановить службу и выполнить `sudo revpn-channel once`, затем запустить службу.
Первый автоматический пост готовится сразу после включения службы. Последующие — через заданный
интервал после успешной публикации. Пропущенные интервалы не догоняются пачкой.

```bash
sudo systemctl stop revpn-channel
sudo revpn-channel configure
sudo revpn-channel login
sudo revpn-channel preview
sudo systemctl start revpn-channel
journalctl -u revpn-channel -n 40 --no-pager
```

## Поведение и ограничения

Текстовые новости из интернета на русском со смайликами и ссылкой на источник.
По умолчанию источник — https://habr.com/ru/rss/news/?fl=ru (технологии и интернет).
RSS/Atom-ленты можно заменить при configure. Берётся один свежий материал не старше 48 часов,
который ещё не публиковался. Из RSS читаются заголовок и описание, а не полный текст страницы.
Модель делает короткий пересказ (до 90 слов). Без свежего источника публикация пропускается.
Маленькая модель может ошибаться: проверь результат через preview перед запуском.
Один URL не публикуется повторно; одинаковые новости на разных сайтах могут повториться.

Очередь SQLite хранит текст и MTProto random_id до отправки. При временном сбое используется тот же ID;
Telegram FloodWait соблюдается. Если неопределённая отправка старше суток, автоматическая повторная
отправка останавливается: нужно проверить, появился ли пост в канале. Абсолютной гарантии отсутствия
дублей после длительного сетевого сбоя нет. Старую очередь без проверки не удалять.

Конфиг: `/var/lib/revpn-channel/channel.json`. Сессия: `/var/lib/revpn-channel/account.session`.
Ollama используется только через `127.0.0.1:11434`. Модель не получает возможности запускать команды.

## Платежи

Новые счета магазина создаются только с `is_test=false`. Установщик автоматически переключает старый
config.json на реальные платежи; остальные настройки и заказы сохраняются. Старые демо-ссылки не
превращаются в реальные. Создай новый заказ. Проверка демо-счёта переводит его на ручную проверку,
доступ за него не выдаётся. Ранее оплаченные реальные заказы продолжают обрабатываться.
