# ReVPN Shop — Telegram + LZT Market + 3X-UI

Готовый проект для Ubuntu 24.04 / Python 3.12: Telegram-бот принимает заказ, создаёт счёт **lzt.market**, проверяет оплату через API и создаёт отдельного клиента VLESS в 3X-UI. Оплаты звёздами в коде нет. Внешние Python-библиотеки, Docker, веб-сайт и публичный webhook не нужны.

## Что умеет

- Срок: 1 час, 6 часов, сутки, неделя, 30/90 дней или своё число часов/дней.
- Трафик: безлимит, 100/500 ГБ или свой объём.
- До подтверждения заказа показывает итоговую цену.
- Ссылка на счёт LZT, автоматическая проверка примерно каждые 30 секунд при небольшой очереди и кнопка проверки.
- Выдача VLESS-ссылки для Happ, повторное получение через «Мои покупки».
- Лимит по сумме входящего/исходящего трафика и срок в настройках клиента 3X-UI.
- Один заказ создаёт один UUID. Повторные нажатия, потерянный ответ API и перезапуск не должны выдавать второй доступ.
- База SQLite хранит заказы и очередь; Telegram и платёжные ответы не считаются подтверждением без проверки реквизитов.
- Тестовые счета LZT никогда не создают настоящий VPN; в тестовом режиме покупать может только администратор.
- Совместимость с новым `/panel/api/clients/add` и старым `/panel/api/inbounds/addClient` (переход на старый только при HTTP 404/405).
- Сервис работает от отдельного системного пользователя, а не root.

Каждая покупка — новый ключ. Автосписания, продление старого ключа, автоматические возвраты, перенос остатка ГБ и партнёрская программа не реализованы. Возвраты обрабатывает владелец магазина через поддержку/LZT.

## 1. Что получить

### Telegram

1. Открой официальный [@BotFather](https://t.me/BotFather).
2. Отправь `/newbot`, задай имя и username.
3. Сохрани токен. Не присылай его в чат, не загружай в публичный GitHub.
4. Нужен **твой числовой Telegram ID**, не username. Если не знаешь — нажми Enter на этом вопросе установщика: он попросит отправить `/start` твоему боту и покажет доступные ID. Выбери именно свой. Токен в URL вручную вставлять не требуется.
5. Подготовь свой `@username` для поддержки покупателей.
6. Используй отдельного бота. Установщик не удаляет чужие webhook; если они настроены, запуск остановится с объяснением.

### LZT Market

Покупка повышения/доступа к API сама по себе ещё не создаёт магазин и нужный токен.

1. Создай API-клиент: https://lolz.live/account/api/client-add
2. Получи Access Token: https://lolz.live/account/api/get-token
3. Для счетов требуется право **`invoice`**. Обычного `market` без `invoice` недостаточно. Не выдавай права на вывод/переводы, если они не нужны.
4. Создай магазин (merchant) на https://lzt.market/merchants и получи его числовой **merchant_id**. Доступность/одобрение магазина определяется LZT.
5. Нужны Access Token и merchant_id. Webhook secret не нужен: этот бот сам опрашивает API.

Прямой адрес платёжного API: `https://api.lzt.market`. Покупателю отправляется URL счёта, который вернул LZT; никакой поддельной платёжной формы нет.

Официальная документация:
- https://lzt-market.readme.io/reference/paymentsinvoicecreate
- https://lzt-market.readme.io/reference/paymentsinvoiceget
- https://lzt-market.readme.io/reference/guide

### 3X-UI

Подготовь логин/пароль панели или API-токен, публичный IP/домен VPN и ID существующего VLESS TCP/RAW подключения. Установщик также умеет создать отдельное подключение.

- На том же сервере путь и порт панели определяются чтением `/etc/x-ui/x-ui.db` без изменения базы.
- API-токен предпочтителен. Если у панели включена 2FA, для фоновой работы используй токен; не отключай 2FA ради бота.
- Общий лимит и дата окончания inbound должны быть нулевыми. Лимиты магазина применяются отдельно к клиентам.
- Поддерживается TCP/RAW с `none`, TLS или REALITY. WS, XHTTP, VLESS Encryption/ML-KEM пока не поддерживаются; установщик откажется их использовать.
- При TLS сертификат должен соответствовать имени, которое импортируется в Happ.
- При REALITY нужны правильные SNI, public key и short ID; закрытый ключ не выдаётся клиенту.

## 2. Установка с телефона

Скачай `ReVPN-Shop.tar.gz`, через SFTP в Termius загрузи в `/root/` сервера. Затем в SSH:

```bash
cd /root
tar -xzf ReVPN-Shop.tar.gz
cd revpn-shop
bash install.sh
```

Установщик запросит секреты локально в терминале. Пароли и токены при вводе не отображаются. Их не нужно присылать разработчику.

По умолчанию предлагается **тестовый режим**. Он позволяет проверить счёт/оплату без выдачи реального VPN. Для запуска с реальными платежами ответь `n` на вопрос о тестовых счетах или позже измени `lolz.test` на `false`.

При выборе inbound:
- Введи ID своего подключения, если оно уже настроено.
- Или введи `0`: будет создан отдельный `ReVPN-Shop`, по умолчанию на порту `21146`.
- Новый inbound создаётся как обычный VLESS/TCP **без TLS/REALITY**. Сам туннель в таком режиме не шифруется; для публичного VPN-магазина разумно подготовить inbound с TLS и выбрать его ID.
- Занятый порт не перехватывается; выбери другой.
- Установщик добавляет TCP-правило в активный UFW/firewalld. Он не включает UFW, не меняет SSH, не сбрасывает правила и не редактирует произвольные nftables/iptables.
- При наличии firewall в панели хостинга разреши тот же TCP-порт там самостоятельно.

Установщик проверяет Telegram, чтение счетов LZT и доступ к inbound, затем запускает systemd-сервис. Во время установки реальный платёж не создаётся.

Файлы:
- `/opt/revpn-shop/` — код;
- `/etc/revpn-shop/config.json` — секреты и цены (root и группа сервиса, режим 0640);
- `/var/lib/revpn-shop/shop.sqlite3` — заказы, ключи и очередь (каталог 0700).

## 3. Цены

Предустановленные цены — стартовые настройки, а не тарифы LZT:

| Трафик и срок | Цена |
|---|---:|
| Безлимит, 1 час | 1 ₽ |
| Безлимит, 1 день | 2 ₽ |
| Безлимит, неделя | 12 ₽ |
| Безлимит, 30 дней | 50 ₽ |
| 100 ГБ, 30 дней | 25 ₽ |
| 500 ГБ, 30 дней | 45 ₽ |

Безлимит: `50 × часы / 720` рублей.
Пакет с лимитом: `20 × часы / 720 + 0.05 × ГБ` рублей.
Цена округляется вверх до целого рубля, минимум 1 ₽. Объём пакета действует на весь выбранный срок, а не каждый день. 1 ГБ в настройках = 1024³ байт.

Изменить:

```bash
nano /etc/revpn-shop/config.json
systemctl restart revpn-shop
```

В секции `pricing`:
- `unlimited_30d_rub`: 50 или 100 — цена безлимита за 30 дней;
- `limited_base_30d_rub`: стоимость времени для лимитного тарифа;
- `per_gb_rub`: стоимость каждого ГБ;
- `minimum_rub`: минимальная стоимость;
- `max_hours`: максимум срока, по умолчанию 8760 часов (365 дней);
- `max_gb`: максимум пользовательского пакета.

Уже созданные заказы сохраняют свою цену. Комиссии LZT не прибавляются ботом автоматически; учитывай их, задавая цены. Не продавай больше трафика, чем позволяет тариф VPS: «безлимит» в боте не отменяет лимиты хостинга.

## 4. Проверка перед продажей

1. Запусти бота с `lolz.test: true` и зайди с admin ID, указанного в настройках.
2. Выбери тариф → «Создать счёт Lolz». Проверь, что ссылка ведёт на LZT и показывает правильную сумму/получателя.
3. Используй тестовые возможности магазина LZT. После подтверждения бот должен показать «Тестовая оплата подтверждена»; нового клиента в панели быть не должно.
4. Переключи `lolz.test` на `false` и перезапусти сервис. Незавершённые тестовые заказы при смене режима не превращаются в реальные: их проверка отклоняется.
5. Сделай собственную небольшую реальную покупку (минимум зависит и от правил LZT). Проверь сумму, статус оплаты, UUID, срок и лимит в панели.
6. Импортируй ключ в Happ и проверь доступ с внешней сети, например мобильного интернета. Чтение API панели не доказывает сетевую доступность Xray.
7. Повтори проверку заказа несколько раз и перезапусти сервис: новый UUID создаваться не должен.
8. Проверь, что после короткого срока доступ отключается. Ограничения исполняет 3X-UI/Xray; отключение может происходить с задержкой учёта, это не обещание до байта/секунды.

В этой поставке прогоняется автоматический набор тестов, включая HTTP-симуляцию потерянного ответа на создание счёта и проверки Mini App-ивентов. Реальные платёжные запросы, твой merchant, VPS и блокировки сети без твоих токенов не проверялись.

Чтение конкретного заказа и назначение повторной проверки:

```bash

```

`retry` не помечает неоплаченный счёт оплаченным и не сбрасывает уже выданный срок. Заказы `review` требуют проверки администратором; автоматический обход проверок не предусмотрен.

Резервная копия:

```bash
systemctl stop revpn-shop
vpnshop backup /var/lib/revpn-shop/backup.sqlite3
systemctl start revpn-shop
```

Скачай резервную копию базы магазина, `config.json` и отдельно резервную копию панели 3X-UI в защищённое место. Они содержат секреты. Не публикуй архивы резервных копий. Восстановление требует согласованных баз магазина и панели; не очищай очередь оплаченных заказов вручную.

Обновление кода: распакуй новый архив в отдельный каталог и запусти `install.sh`. Существующий конфиг и база не удаляются. Если настройка не завершилась после создания inbound, повторный запуск ищет уже созданный `ReVPN-Shop`.

## 6. Как устроена проверка платежа

- Сервер сам рассчитывает цену; callback покупателя не может задать сумму.
- `payment_id` — случайный идентификатор заказа, постоянный при повторных запросах.
- Каждый заказ привязан к Telegram ID. Кнопка другого пользователя не выдаст чужой ключ.
- Сверяются merchant_id, invoice_id, payment_id, метаданные заказа, сумма, режим test/live и `paid` с датой оплаты.
- В текущей схеме LZT ответ InvoiceModel содержит целое `amount`, но не документирует единицы и не требует поля currency. Поэтому бот всегда создаёт счёт в `rub`, сохраняет сумму из авторизованного ответа создания и требует её неизменности при оплате. Если поле currency присутствует, также проверяет `rub`. Восстановление создания идёт по тому же уникальному payment_id и метаданным с ценой в копейках.
- Callback URL и сообщение «я оплатил» не являются основанием выдачи.
- Истёкшие счета продолжают проверяться с меньшей частотой, чтобы не терять поздние подтверждения.
- При сбое панели оплаченный заказ остаётся в очереди. UUID и subId записаны до обращения в панель; повторная попытка сначала ищет существующего клиента.
- Срок нового клиента начинается непосредственно перед созданием. Если первая попытка не создала клиента, повторная выдача даёт полный срок. Если клиент уже существует, срок не продлевается.
- Доставка Telegram выполняется после сохранения ключа. При сбое сообщения ключ доступен через «Мои покупки».
- Обработчик один; второй процесс блокируется файловой блокировкой. Это проект для небольшого магазина, не кластер высокой нагрузки.

## 7. IP и защита от DDoS

Шифрование текста VLESS-ссылки, Base64 или домен не скрывают адрес VPN от покупателя: клиент должен подключиться к конечному IP. При желании в `panel.public_host` укажи домен вместо IP; DNS всё равно раскрывает адрес.

Для защиты нужен провайдер с защитой L3/L4 от DDoS или отдельный защищённый TCP-узел перед исходным сервером. Тогда пользователи подключаются к защищённому узлу, а исходный сервер принимает VPN-трафик только от него. Такой узел должен быть реально настроен; простая замена адреса в конфиге недостаточна. Обычный HTTP/CDN proxy не проксирует произвольный VLESS/TCP.

Публичный webhook здесь не требуется; бот не открывает дополнительный HTTP-сервер. Порт панели и порт VPN — разные вещи.

## Mini App: ивенты

В Mini App есть серверные бонусные ивенты. Ивент активен **60 минут**, затем идёт **10 минут перерыва**. Пул содержит **1000 вариантов** с уникальными названиями и кнопками; порядок меняется псевдослучайно без повторения одного и того же полного цикла раньше, чем будут пройдены все 1000 вариантов.

Каждый засчитанный тап даёт **ровно +1 секунду VPN**. Секунды сначала копятся на сервере, а затем применяются к одной отдельной бонусной VPN-подписке пользователя; новый VLESS-клиент на каждый тап не создаётся. Для первого применения нужно накопить минимум 30 секунд, чтобы ключ не успел истечь во время выдачи. Следующие применения продлевают тот же бонусный профиль.

Защита от простых автокликеров работает на сервере: Telegram Mini App `initData` проверяется по подписи Bot API, каждый тап использует одноразовый nonce, есть лимиты частоты, проверка слишком ровного ритма, временный cooldown, меняющаяся позиция кнопки и периодические мини-проверки. Клиентская цифра сама по себе награду не выдаёт. Это защита от обычной автоматизации, а не обещание абсолютной неуязвимости.

Ивенты не используют LLM или внешний AI API во время работы: варианты генерируются детерминированно из встроенного пула, поэтому функция не требует дополнительных ключей и не создаёт расходов на модель.

## Тарифы и доставка

Магазин предлагает четыре товара: обычный VLESS, мобильный режим для белых списков, набор обычный + мобильный режим и MTProto. Цены по умолчанию: 50/100/150/25 ₽ за 30 дней. Перед оплатой мобильного режима выбирается оператор. В каталоге есть МТС, МегаФон, Билайн, T2/Tele2, Yota, Т-Мобайл, СберМобайл, Альфа-Мобайл, Ростелеком, ГПБ Мобайл, Волна и Мотив.

Для каждого оператора можно задать свой набор узлов в `operator_nodes`. Если для оператора отдельный набор не задан, используется прежний набор `max/yandex/disk/vk/vkvideo`. Это позволяет постепенно заводить реально проверенные точки входа для конкретных сетей, не ломая существующие подписки.

ReVPN теперь умеет экспортировать не только VLESS TCP/RAW, но и VLESS XHTTP с TLS/REALITY. Для XHTTP сохраняются `path`, `host` и `mode`; XTLS Vision не добавляется к XHTTP с обычным `encryption=none`, потому что такой flow ломает этот транспорт. TCP/RAW с TLS/REALITY по-прежнему использует Vision.

Важно: один только «правильный SNI» не превращает зарубежный дата-центровый IP в рабочий узел во время настоящего режима белого списка. Если оператор режет трафик по IP/CIDR до TLS, нужна реально достижимая точка входа в разрешённой сети/CDN либо другой заранее проверенный маршрут. Поэтому ReVPN не импортирует чужие публичные VLESS-ключи автоматически.

Оплаченная VLESS покупка получает один URL подписки Happ. Для набора в нём находятся все выбранные профили. Лимит ГБ распределяется между профилями, чтобы общий объём не умножался. Заголовок Happ содержит имя Telegram (first name) и дату окончания, например `Ольга🥶ReVPN · 29.10.26`. Кнопка выдачи открывает страницу `happ://add/...`, а резервная HTTPS-ссылка остаётся в сообщении.

### Мобильная сеть и белые списки

Установщик применяет консервативные TCP-настройки для мобильных сетей: `tcp_mtu_probing=1`, TCP Fast Open и, если ядро поддерживает, `fq + BBR`. Это уменьшает задержку при очередях/потерях, но не может убрать физический RTT или блокировку оператора.

Диагностика текущего обычного VPN без вывода секретов:

```bash
sudo revpn-netdiag
```

Команда покажет транспорт/security обычного inbound, публичный порт, SNI, BBR/MTU-настройки и базовую связность VPS. Если обычный профиль всё ещё VLESS RAW без TLS/REALITY, диагностика явно это отметит.

Для справки по актуальным публичным спискам разрешённых SNI/CIDR можно обновить локальные копии:

```bash
sudo revpn-whitelist refresh
sudo revpn-whitelist status
```

ReVPN загружает только справочные списки доменов/CIDR из публичных репозиториев `igareck/vpn-configs-for-russia` и `hxehex/russia-mobile-internet-whitelist`. Чужие proxy/VLESS credentials не импортируются и пользовательский трафик третьим лицам не передаётся.

MTProto использует закреплённый upstream `vendor/mtprotoproxy.py`. Платные секреты появляются только у активных заказов и удаляются после expiry. Бесплатный прокси включается лишь с рекламным `AD_TAG`, выданным официальным @MTProxyBot через `/newproxy`; реклама Telegram показывается самим Telegram.

По умолчанию сайт остаётся на своей исходной схеме: nginx напрямую принимает HTTPS на публичном TCP/443. MTProto не делит этот порт с сайтом: платный прокси публикуется на 2443, бесплатный — на 3443 (или на других отдельных портах из конфига). Это основной и рекомендуемый режим ReVPN.

Экспериментальный `edge443` оставлен в коде как выключенная опция. Если его вручную включить, он может разделять один TCP/443 по FakeTLS SNI между HTTPS и MTProto. При последующем отключении установщик автоматически останавливает edge-сервис и возвращает nginx с локального 4443 обратно на публичный 443.

Для бесплатного MTProto регистрируй в @MTProxyBot фактический публичный порт из `mtproto.free.public_port`/ `port` и базовый secret без клиентских префиксов `ee/dd`. Квоты MTProto по гигабайтам не заявляются, потому что upstream не хранит их надёжно после перезапуска.

## Запуск

1. Укажи DNS для домена подписок и HTTPS reverse proxy на `127.0.0.1:8090` (в конфиге `subscription.public_base`).
2. Запусти `sudo bash install.sh` и введи токен BotFather, ID магазина LZT, данные 3X-UI, существующий inbound и URL подписок.
3. Для мобильных/белых профилей укажи реально работающие TCP/RAW или XHTTP inbound. Если профиль или оператор не прошёл тест именно в нужной мобильной сети, оставь его выключенным: бот не должен продавать непроверенный маршрут.
4. Для бесплатного MTProto зарегистрируй прокси у `https://t.me/MTProxyBot` на фактическом публичном порту (по умолчанию 3443). Базовый secret отправляется без клиентских префиксов `dd/ee`.
5. Mini App содержит 1000 ротационных событий: тап-гонку, ловлю падающих снежинок, реакцию и разбивание кристалла. Награды бывают секундами VPN, бонусными рублями или смешанными. Бонусные рубли хранятся в SQLite в копейках и автоматически уменьшают следующую оплату; сервер ограничивает максимальную рублёвую награду на один ивент.

Тесты запускаются так:

```bash
cd /opt/revpn-shop
PYTHONPATH=. python3 -m unittest discover -s tests -v
```

Для проверки тестовых платежей оставь `lolz.test=true`; перед реальной продажей поставь `false`, повторно выполни `vpnshop check` и проверь один маленький платёж вручную.
