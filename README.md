# ReVPN

ReVPN is an Android VPN client for a personal Xray server.

## What the stack does

- Android `VpnService` creates the system TUN interface and captures device traffic.
- VLESS carries that traffic between the phone and the Xray server.
- XTLS Vision is the optimized VLESS flow used with TCP/RAW.
- REALITY provides the TLS-looking transport layer and configurable SNI/fingerprint profile.
- HAProxy on the VPS can route several REALITY profiles through the same public TCP/443 port.

VLESS is therefore not the camouflage itself. It is the lightweight proxy protocol inside the connection. REALITY is the part responsible for the TLS appearance.

## Current app features

- dark mobile UI inspired by the supplied references
- animated connect button and connection pulse
- one-tap connect/disconnect
- multiple server profiles
- selectable REALITY profiles
- built-in profile labels for MAX, VK, VK Video and Yandex Disk
- Android foreground notifications for Connecting / Connected / Disconnected
- notification Connect / Disconnect actions
- quota and account status in notifications
- Google Sign in through Android Credential Manager
- guest traffic limit: 1 GiB
- signed-in Google account: unlimited traffic in the current development version
- import of the server JSON generated by the VPS installer
- Android 5.0+ (`minSdk 21`)
- official `XTLS/libXray` Android AAR, downloaded at build time
- GitHub Actions APK build

## Google sign-in setup

ReVPN uses Google's current Credential Manager Sign in with Google flow.

1. Open Google Auth Platform / Google Cloud Console.
2. Create an OAuth 2.0 **Web application** client.
3. Configure your consent screen.
4. Copy the Web Client ID ending in `.apps.googleusercontent.com`.
5. Either:
   - add it to the repository Actions secret named `GOOGLE_WEB_CLIENT_ID`, or
   - open ReVPN -> Settings -> Google OAuth and paste the Web Client ID there.

The app does not store the Google ID token. It stores only the selected account ID, email, display name and optional avatar URL.

### Development auth note

The current version treats a successful Google Credential Manager response as a signed-in account locally. For a production service, the Google ID token must be sent to a backend and verified there before the backend grants an unlimited plan. Traffic quotas should also be enforced server-side in production so clearing app data or modifying the APK cannot reset or bypass them.

## Traffic limits

- Guest: 1 GiB cumulative VPN traffic.
- Google account: unlimited in the current development build.
- Guest usage is stored locally and updated while the VPN tunnel is active.
- If the guest limit is reached, ReVPN disconnects the VPN and asks the user to sign in.

## Important limitation of whitelist mode

Changing SNI or the TLS fingerprint does **not** change the destination IP of the connection. If a mobile network allows only the actual IP ranges of selected services, a random VPS IP can still be blocked before REALITY starts.

The selectable MAX/VK/VK Video/Yandex Disk entries in ReVPN are REALITY/SNI profiles. They are useful only on networks where the route to the VPS itself is reachable and the filtering happens at a layer where this TLS appearance matters.

## Production build

The store-ready build has no in-app server JSON or OAuth developer fields. Production values are injected by GitHub Actions secrets and become part of the release artifact.

Required repository Actions secrets:

- `REVPN_SERVER_CONFIG_BASE64` — base64 of the generated `/root/revpn-client.json`
- `GOOGLE_WEB_CLIENT_ID` — Google OAuth Web Client ID
- `ANDROID_KEYSTORE_BASE64` — base64 of the release signing keystore
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

Run `Actions -> Build Production Release -> Run workflow`. The resulting `ReVPN-production` artifact contains a signed release APK and AAB.

The app includes two user-facing connection modes:

- **VPN** — ordinary encrypted VPN profile
- **Белый список** — selectable compatibility profiles such as MAX, VK, VK Video and Yandex Disk

The production Settings screen contains appearance options only: Glass, Night, Day, Red, Blue and Purple.

## Build APK

GitHub Actions automatically builds a debug APK after Android source changes.

Open:

`Actions -> Build Android APK -> latest successful run -> Artifacts -> ReVPN-debug`

For a local build:

```bash
bash scripts/fetch-libxray.sh
gradle -PGOOGLE_WEB_CLIENT_ID="YOUR_WEB_CLIENT_ID" :app:assembleDebug
```

## Ubuntu 24.04 server

On the VPS:

```bash
sudo apt update
sudo apt install -y git
git clone https://github.com/ReVerfyx/ReVPN.git
cd ReVPN
sudo bash server/install.sh
```

The installer writes the Android client configuration to:

```
/root/revpn-client.json
```

For production, do not paste this file into the app. Encode it as base64 and store it in the private GitHub Actions secret `REVPN_SERVER_CONFIG_BASE64`. The release workflow embeds it into the APK/AAB at build time.

For extra servers, merge the server objects into one `servers` array before encoding the production configuration.
